# Восстановление списков при сетевой ошибке

`MainFragmentContent` загружает сохранённые записи Room параллельно с первым запросом Volley. Карточки из базы передаются в собственный снимок адаптера через `updateFeed()`. Успешный ответ первой страницы заменяет сохранённый список; позднее чтение базы не возвращает устаревшие записи поверх свежих.

При ошибке сети список остаётся доступным, появляется пояснение и кнопка повторной загрузки. Если подходящих данных нет, отображаются иконка отсутствия связи, текст о повторном обновлении после улучшения сигнала сети и кнопка «Обновить». Отдельно обрабатывается успешный пустой ответ: старые записи не возвращаются после него. Отказ загрузки следующей страницы сохраняет карточки и повторяет именно эту страницу, не пропуская её.

Снимки различаются по разделу, вкладке, категории, набору выбранных категорий, поисковой строке, режиму ожидания одобрения и аккаунту избранного. Параметры передаются через аргументы фрагментов; глобальные события не меняют уже открытый запрос. Запросы отменяются при смене списка и уничтожении представления, а устаревшие обратные вызовы дополнительно отсекаются поколением представления и запроса. HTML и все поля API сохраняются в исходном JSON, без удаления разметки. URL запросов и содержимое ответов не выводятся в журнал загрузки списка.

Таблица `feed_pages` сохраняет до пяти первых страниц для каждого из сорока последних вариантов списка. Успешная первая страница удаляет прежние последующие страницы этого варианта. Из старой таблицы `data` допускается восстановление только обычного списка раздела без поиска и фильтров; избранное, подробная вкладка и общий раздел «Новое» используют только точный снимок своего запроса. После показа кэша подгрузка следующих страниц начинается после успешного обновления первой страницы, чтобы не смешивать старый и новый порядок записей.

Миграция Room 7 → 8 добавляет таблицу снимков и сохраняет прежние записи и отметки прочтения. Очистка старых записей сравнивает Unix-время с числовой границей тридцати дней. Раньше сравнение с текстовым результатом `date()` удаляло даже свежие записи при запуске. Команда очистки кэша удаляет обе таблицы сохранённого содержимого, сохраняя отметки прочтения.

Восстановление относится к спискам материалов в `MainFragmentContent`, включая главную, видео, новости, остальные разделы материалов, подробную вкладку, категории, поиск и избранное. Форма ЛС, комментарии, дерево категорий и форум используют собственные загрузчики и этим снимком не подменяются. Изображения по-прежнему загружает Glide: наличие JSON в базе не гарантирует, что каждая иллюстрация уже сохранена на устройстве.

Проверено в облачной среде: сборка `DVClient_GoogleDebug`, 235 unit/Robolectric-тестов без ошибок и пропусков, Android Lint без ошибок (645 существующих предупреждений, 2 подсказки). Подпись собранного debug APK проверена `apksigner`. В этом изменении добавлено 39 тестов, в том числе проверки настоящей миграции SQLite, хранения после перезапуска, сетевых ошибок, гонок базы и Volley, кратких страниц API и индекса прочтения фильтрованного списка. Физическое устройство и эмулятор в среде отсутствуют.
